# Redis bgsave 写时复制究竟是谁触发缺页中断

bgsave 通过 fork 子进程配合写时复制（Copy-On-Write）实现全量快照。小林 coding 说"子进程访问副本完成快照"，这是不对的。

## 写时复制（COW）原理

fork 之后：

1. 父子进程的**页表相同**，指向同一块物理内存
2. 内核将这块物理内存标记为**只读**
3. **父进程**尝试写入时触发**缺页中断**
4. 内核复制该页到新的物理块，修改父进程页表指向新块
5. 父进程在**新块**上写入，子进程仍读**原块**

## 关键点：是谁触发缺页中断？

**是父进程，不是子进程。**

子进程只负责读取原块的数据写入 RDB 文件，不触发写入，所以不会触发缺页中断。

快照期间，父进程继续处理客户端请求，每次写入都会触发缺页中断，内核按需复制内存页。子进程看到的始终是 fork 时刻的内存状态。

## 实际影响

这个理解偏差不影响使用，但在排查 bgsave 期间内存增长问题时很重要：

- 内存增长量 = fork 后父进程**实际修改的页数** × 页大小
- 不是"复制了一份完整内存"，而是按需复制
